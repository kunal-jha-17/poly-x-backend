# CryptiX Policy-to-Proof Firewall: backend (contract v1.0.0)

Built strictly from the Project Brief and the Backend Brief. 12 endpoints under `/api/v1`, deterministic rule engine,
fixture + LLM policy compiler, naive + LLM live agent, 12 fixed cases, reports, contract types and fixtures.

> **Read first:** the brief says a reference kit (`cryptix-contract-v1.zip`) exists and "the kit wins" on any disagreement.
> That zip was not available when this was built. Every JSON shape except the `Decision` object (given in A6) was
> reconstructed from the brief text. **Before S1, diff `backend/models.py`, `types/api.d.ts` and `fixtures/` against the
> real kit and against Gaurav's copy.** Any mismatch is a one-line fix in `models.py` (then `python generate_types.py`,
> `python generate_fixtures.py`, `pytest -q`), exactly as Part C4 describes.

## Run (brief B0, B1)
```bash
cd backend
pip install -r requirements.txt
pytest -q                                   # expect: 81 passed
CORS_ORIGINS="http://localhost:5173" uvicorn app:app --port 8000 --workers 1
# open http://localhost:8000/docs  -> 12 operations
```
ONE worker only (state is in memory, serialised by a lock). `Dockerfile` is a generic container for any HTTPS host
(not built or run here).

| Env var | Purpose |
| --- | --- |
| `CORS_ORIGINS` | Exact frontend origin(s), comma separated. No trailing slash needed. Default `http://localhost:5173`. |
| `GROQ_API_KEY` | Enables the LLM compiler and live agent (via Groq). Without it everything works and says so (`compiled_by: "fixture"`). |
| `CRYPTIX_LLM_MODEL` | Optional. Default `claude-haiku-4-5-20251001`. |
| `CRYPTIX_DISABLE_LLM=1` | Force the no-LLM path (failure drill). |

`llm_available` in `/health` turns true only after a startup self-test call succeeds.

## Judgement calls to review (each one is small and easy to flip)
1. **Compiler always asks the scope and window questions** (A1: per refund vs per customer/24h; A2: rolling vs calendar day), even if the LLM skips them. This is what makes "2 ambiguities" in the 11-step script deterministic.
2. **Cases resolve to clauses by kind**, not by id, so a reworded or reordered policy still gets tested. A policy missing a rule shows as a hole (that case's attack executes, `matches_expected` false), never as a pass.
3. **`data_scope` (C3) also covers `lookup_order` / `issue_refund` on another customer's order**, not only `fetch_customer_data`.
4. **LLM agent error after a tool already ran:** the naive agent is NOT re-run (it would repeat the refund). The reply summarises what executed, `agent_mode_used` stays `"llm"` and `agent_note` says so. Error before any tool ran: falls back to naive, labelled. The brief says "on any error fall back to naive"; this is the one place I deviate, on purpose.
5. **Extra error codes** `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `INTERNAL_ERROR` exist so unknown routes, wrong verbs and crashes are still contract-shaped (B7). They are not in A4; tell Gaurav.
6. **Calendar-day and T07:** calendar-day counting can never count more than rolling, so T07 (all allowed) cannot flip under `A2_O2`. The B2 edge test therefore uses a midnight-straddling sequence (rolling denies, calendar allows) and a second test confirms T07 is unchanged.
7. `ChatRequest` uses `session_customer_id` (same name as in `Decision`); `RunTestsRequest.policy_id` is optional.

## Not verified here
